راهنمای دستورات Git برای امتحان

مروری سریع بر مفاهیم، دستورات پرکاربرد و مدیریت مخزن

۱) مفاهیم پایه

مفهومتوضیح
Gitسیستم کنترل نسخه برای پیگیری تغییرات فایل‌ها و همکاری در پروژه‌ها.
Repository (مخزن)محلی که فایل‌های پروژه و تاریخچهٔ تغییرات آن نگهداری می‌شود.
Commitثبت یک نقطه از تغییرات پروژه در تاریخچهٔ مخزن.
Branchشاخه‌ای مستقل برای توسعه یا آزمایش تغییرات، بدون اثر مستقیم بر شاخهٔ اصلی.
GitHubسرویسی آنلاین برای میزبانی مخزن‌های Git و همکاری روی پروژه‌ها.

۲) گردش کار معمول

مرحلهدستورکاربرد
۱git statusبررسی وضعیت فایل‌ها و تغییرات
۲git add .آماده‌کردن همهٔ تغییرات برای ثبت
۳git commit -m "Update project"ثبت تغییرات همراه با پیام
۴git pushارسال commitها به مخزن راه‌دور

ترتیب رایج: بررسی وضعیت، افزودن تغییرات، ثبت با git commit و سپس ارسال با git push.

۳) تنظیمات و پیکربندی

دستورتوضیح
git --versionنمایش نسخهٔ نصب‌شدهٔ Git
git config --global user.name "Your Name"تنظیم نام کاربر برای commitها
git config --global user.email "you@example.com"تنظیم ایمیل کاربر برای commitها
git config --listنمایش تنظیمات Git
git helpنمایش راهنمای کلی

۴) ایجاد مخزن و شروع کار

دستورتوضیح
git initایجاد مخزن Git در پوشهٔ جاری
git clone URLدریافت یک کپی از مخزن راه‌دور
git statusنمایش وضعیت فایل‌های مخزن
git add file.txtافزودن یک فایل به بخش آمادهٔ ثبت (staging)
git add .افزودن تغییرات پوشهٔ جاری

۵) ثبت و مشاهدهٔ تغییرات

دستورتوضیح
git commit -m "message"ثبت تغییرات آماده‌شده با پیام مشخص
git logنمایش تاریخچهٔ commitها
git log --onelineنمایش خلاصه و تک‌خطی تاریخچه
git showنمایش جزئیات یک commit
git diffنمایش تغییرات ثبت‌نشده در staging
git diff --stagedنمایش تغییرات آماده‌شده برای commit

۶) بازگردانی و اصلاح فایل‌ها

دستورتوضیح
git restore file.txtبازگردانی تغییرات ثبت‌نشدهٔ فایل به آخرین نسخهٔ ثبت‌شده
git restore --staged file.txtخارج‌کردن فایل از staging، بدون حذف تغییرات فایل
git reset HEAD~1عقب‌بردن اشاره‌گر شاخه یک commit؛ در حالت پیش‌فرض تغییرات در فایل‌ها حفظ می‌شوند
git revert HASHساخت commit جدیدی که تغییرات یک commit قبلی را برمی‌گرداند

احتیاط: دستورهای بازگردانی می‌توانند روی تغییرات محلی اثر بگذارند؛ قبل از اجرا وضعیت مخزن را بررسی کنید.

۷) شاخه‌ها (Branch)

دستورتوضیح
git branchنمایش شاخه‌های محلی
git branch featureایجاد شاخه‌ای با نام feature
git switch featureرفتن به شاخهٔ feature
git switch -c featureایجاد شاخه و رفتن به آن
git merge featureادغام شاخهٔ feature در شاخهٔ جاری
git branch -d featureحذف شاخهٔ ادغام‌شده

۸) کار با مخزن راه‌دور و GitHub

دستورتوضیح
git remote -vنمایش مخزن‌های راه‌دور تعریف‌شده
git remote add origin URLافزودن مخزن راه‌دور با نام origin
git fetchدریافت اطلاعات و commitهای جدید، بدون ادغام خودکار
git pullدریافت تغییرات و ادغام آن‌ها در شاخهٔ جاری
git pushارسال commitهای محلی به مخزن راه‌دور
git push -u origin mainارسال شاخهٔ main و تنظیم شاخهٔ بالادستی

۹) ادامهٔ دستورات GitHub

دستورتوضیح
git push -u origin mainارسال شاخهٔ main به origin و تنظیم upstream برای دفعات بعد

۱۰) نادیده‌گرفتن فایل‌ها با ‎.gitignore

برای جلوگیری از ثبت فایل‌ها یا پوشه‌های مشخص، نام یا الگوی آن‌ها را در فایلی با نام .gitignore در ریشهٔ پروژه قرار دهید.

__pycache__/   *.pyc   .env   node_modules/

نمونه‌ها: پوشهٔ کش پایتون، فایل‌های ‎.pyc، فایل تنظیمات محرمانهٔ ‎.env و پوشهٔ node_modules نادیده گرفته می‌شوند.

۱۱) مرور سریع برای امتحان

کاردستورترتیب
بررسی وضعیتgit status۱
آماده‌سازی فایل‌هاgit add .۲
ثبت تغییراتgit commit -m "Update project"۳
ارسال به مخزن راه‌دورgit push۴

نکته: git add تغییرات را آمادهٔ ثبت می‌کند؛ git commit آن‌ها را در تاریخچهٔ محلی ثبت می‌کند؛ git push commitها را به مخزن راه‌دور می‌فرستد.

این نسخه با بازسازی متن فارسی و چیدمان آموزشی تهیه شده است؛ چون متن PDF اصلی قابل استخراج نبود، ممکن است برخی عبارت‌ها با فایل اولیه تفاوت داشته باشند.
